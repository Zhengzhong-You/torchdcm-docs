    Build a new module with an agent¶

    Start from the research change, not a new estimator. Identify the observation unit, the mechanism that changes, and the conditioning information of the query. Choose an existing interface before adding a shared operator.

    Requirement

    Starting point

    Change a utility

    ModuleChoiceModel.from_utility

    New observed probability or density

    ObservationBatch and LikelihoodModel

    Shared latent variables or measurements

    LogFactor, join, sum_by, integrate

    Hidden-state sequence

    markov_eliminate and an explicit forecast

    Smooth inner problem

    implicit_root or implicit_fixed_point

    Moment restrictions

    GMMModel

    A reusable prompt¶

    Extend the existing model with [new mechanism].
State the independent observation unit and prediction information.
Read AGENTS.md and the TorchDCM extension skill.
Reuse existing normalization, integration, recursion and estimation.
Add only the missing mechanism and its explicit query.
Check probabilities or moments and first/second derivatives independently.
Count all task-specific code, including helpers, adapters and core changes.
Report scope, convergence and the verification performed.

    Acceptance¶

    Use an independent formula, enumeration or numerical reference for a small case. Check grouping, parameter constraints, shared latent variables and unavailable alternatives. Prediction tests should not depend on withheld response labels. Record any human repairs needed for acceptance. A small wrapper does not make hidden task-specific helpers free.

    The skill applies the same statistical requirements to human and agent changes. It is guidance read by a coding agent, not an automatic natural-language compiler or a measured guarantee of development success.

    Download the extension skill. In the development package it lives at .agents/skills/torchdcm-extension/SKILL.md and is linked from AGENTS.md.

    Run the development checks¶

    From the software repository root, install the test dependency and run the checks relevant to the new mechanism:

    python -m pip install -e ".[dev]"
python -m pytest -q tests/test_module_choice.py tests/test_composition_contract.py tests/test_event_markov.py tests/test_implicit.py tests/test_derivatives.py tests/test_problem_families.py tests/test_general_combinations.py
python -m pytest -q

    Add an independent numerical reference for the new mechanism rather than relying only on the existing regression suite. Record any CUDA skip separately from checks that actually ran. The downloaded skill belongs inside its expected repository directory so its links to the extension guides remain valid.
